# 钩织小管家 🧶

一个单文件的钩织记录工具：管毛线库存，也管项目进度。

写给那种**线囤了一柜子、项目开了七八个、但记不清哪团线配几号针**的人。

不用装任何东西，Python 3.7 以上直接跑，所有数据存在本地一个 JSON 文件里。

```powershell
py crochet.py 加线 苏苏姐家 四股牛奶棉 棉 50 130 12.8 --color 奶白 --code 01 --skeins 2
py crochet.py 加项目 小鲸鱼玩偶 2.5mm --total 60 --yarn w01:60
py crochet.py 列
```

---

## 它解决三个问题

**「我这条线以前用几号针钩的？」**
拿一条线反查它参加过哪些项目、用的什么针号。针号会自动归一，`2.5mm`、`2.5`、`2.5 号` 都认成同一根针。

**「这个颜色我到底还剩多少？」**
同一种颜色买过三个牌子、四个批次时，分开记是灾难。按颜色归到一起算总数，还告诉你以前用这个色最多一次用掉多少克 —— 够不够织一件，心里就有数了。

**「账怎么对不上？」**
一团 50g 的线织进去 46g，剩 4g 是回不去的碎头。这 4g 既不是「还能用的库存」，也不是「织进作品里的线」。工具会把它单独记成**零头**，让库存能真的对上。

## 安装

需要 Python 3.7+（开发测试用的是 3.7.3）。

```powershell
py --version    # 先确认有
```

没有的话去 [python.org](https://www.python.org/downloads/) 装一个，安装时记得勾上 **Add Python to PATH**。

然后把 `crochet.py` 放到你想放的文件夹，`cd` 进去就能用。不需要 `pip install` 任何东西。

> Windows 上敲 `py` 比 `python` 可靠：微软商店那个 python 别名有时候会静默失败。

## 命令一览

每个命令都有中英文两个名字，敲哪个都行。

### 记库存

| 命令 | 作用 |
| --- | --- |
| `加线 <品牌> <系列> <材质> <克重> <长度> <价格>` | 入库一卷线，自动编号 `w01`、`w02`… |
| 可选参数 | `--color 奶白` `--code 01` `--skeins 2`（买了几团，默认 1） |
| `列 [关键字]` | 库存 + 项目一览，带总额统计 |
| `同色 [关键字]` | 按颜色汇总；不带参数列全部颜色 |
| `反查 <线>` | 这条线用过哪些针号、织过什么 |
| `用完一团 <线>` | 手上那团用光了：零头记损耗，库存对齐整团 |
| | `--force` 零头超过半团时也照丢（默认会拦一下） |

### 记项目

| 命令 | 作用 |
| --- | --- |
| `加项目 <名字> <针号>` | 开新项目，自动编号 `p01`、`p02`… |
| 可选参数 | `--link <教程链接>` `--total 60` `--unit 圈` `--yarn w01:60`（可重复） |
| `推进 <项目> [数量]` | 推进进度，默认 +1；到 100% 自动标完工 |
| `看 <项目>` | 看单个项目详情 |
| `用线 <项目> <线> <克数>` | 登记用料，同时扣库存 |
| `收尾 <项目>` | 织完了：核对实际用量、处理零头、剩线归位 |
| | `--usage w01:58` 直接指定用量不问；`--yes` 全程用默认值 |

`<线>` 和 `<项目>` 都可以填编号（`w01` / `p01`），也可以填名字或其中几个字。**名字有歧义时用编号**，它绝对唯一。

### 通用

`--data <路径>` 换存档位置，放在任意命令前后都行：

```powershell
py crochet.py --data D:\备份\my_yarn.json 列
```

## 一次完整的流程

**开工前，把线入库：**

```powershell
py crochet.py 加线 苏苏姐家 四股牛奶棉 棉 50 130 12.8 --color 雾霾蓝 --code 01 --skeins 3
# 已入库 → w01 苏苏姐家·四股牛奶棉 | 棉 | 雾霾蓝(01) | 50g/130m | ¥12.80 | 剩 150g（≈3.0 团）

py crochet.py 加线 雪妃尔 五股 腈纶 100 200 19.9 --color 雾霾蓝 --code 37
# 已入库 → w02 雪妃尔·五股 | 腈纶 | 雾霾蓝(37) | 100g/200m | ¥19.90 | 剩 100g（≈1.0 团）
```

**开项目，先估个用量：**

```powershell
py crochet.py 加项目 小鲸鱼玩偶 2.5mm --link "https://..." --total 60 --yarn w01:60
```

**织的过程中随手推进：**

```powershell
py crochet.py 推进 小鲸鱼玩偶 12
```

**中途发现另一条线也得用上：**

```powershell
py crochet.py 用线 小鲸鱼玩偶 w02 35
```

**织完了：**

```powershell
py crochet.py 推进 小鲸鱼玩偶 48
# 🎉 完工！接着跑 `py crochet.py 收尾 p01`，趁线还在手边，把实际用量和剩线一次核对掉。

py crochet.py 收尾 小鲸鱼玩偶
```

收尾会问你两件事（用几条线就问几遍）：

```
🧶 收尾「小鲸鱼玩偶」  进度 60/60 圈

① 核对实际用量 —— 回车就沿用已记的数字
   w01 苏苏姐家·四股牛奶棉 雾霾蓝 · 已记 60g，实际用了多少？ [60]
      w01 → 60g 改成 148g，库存跟着补差
   w02 雪妃尔·五股 雾霾蓝 · 已记 35g，实际用了多少？ [35]
      w02 → 35g ✓

② 剩线怎么处理 —— 默认全部放回库存
      w01 剩 2g 零头
         这 2g 不要了、记成零头吗？ [y/N]
         → 留着，放回库存
      w02 剩 65g → 放回库存

③ 收尾完成
   ✅ 小鲸鱼玩偶 已标成完工，共用料 183g，约值 ¥44.85
```

**过几个月，想不起来那条线用几号针：**

```powershell
py crochet.py 反查 雾霾蓝
```

```
w01 苏苏姐家·四股牛奶棉 | 棉 | 雾霾蓝(01) | 50g/130m | ¥12.80 | 剩 2g（≈0.0 团）

   这条线你用过这些针号：
     2.5mm  →  小鲸鱼玩偶

   （共 1 个项目）
```

同一条线织过好几个项目时，会按针号归组列出来，比如 `2.5mm → 小鲸鱼玩偶` / `3mm → 兔子挂件、杯垫`。

## 数据存在哪

默认是**脚本旁边**的 `crochet_data.json`，纯文本 JSON。

- **每次改动立刻存盘**，不用记得按保存
- 写的时候先写临时文件再替换，写到一半断电不会毁存档
- 存档读不出来时，会自动改名成 `.broken` 保留下来，不会让程序拿空库把原文件盖掉
- 兼容记事本存出来的「UTF-8 带 BOM」格式

**手动备份**就是复制这个文件。想备份到别处，用 `--data` 指过去：

```powershell
py crochet.py --data "D:\OneDrive\毛线账.json" 加线 ...
```

## 当库用

不想敲命令的话，import 进来自己写：

```python
from crochet import Store, Yarn, Project

store = Store()                                   # 自动读取 crochet_data.json

y = store.add_yarn(Yarn("雪妃尔", "五股", "腈纶", 100, 200, 19.9, "雾霾蓝", "37"))
p = store.add_project(Project("兔子挂件", "3.0mm", total=20))

store.use(p, y, 35)          # 登记用料，同时扣库存
store.set_usage(p, y, 32)    # 改用量，库存按差额补正
store.advance(p, 5)          # 推进进度

print(store.yarn_report(y.yarn_id))   # 反查
print(store.color_report("蓝"))        # 同色汇总
```

`Yarn` 的字段：`brand` `series` `material` `weight_g` `length_m` `price` `color` `color_code` `skeins` `used_g` `waste_g`。

`Project` 的字段：`name` `needle` `yarns` `link` `current` `total` `unit` `status`。

## 几个设计上的取舍

写下来是因为过几个月再看代码，这些理由不会自己浮出来。

**收尾不改进度数字。** 你实际织到 40 圈就停了，那是真实发生过的事。收尾只标状态成「完工」，不会把进度悄悄抹平成 100%。

**`--yes` 一条线都不丢。** 丢弃还能用的线是不可逆的，线进了「零头」库存就回不去了。所以哪怕在图省事的批量模式下，默认也是「全部放回库存」，要记零头得手动敲 `y`。

**针号按数值归一。** `3mm` 和 `3.0mm` 如果当成两根针，反查结果就散了。归一之后显示仍用你原本的写法。

**零头超过半团会拦一下。** 「用完一团」是减库存的动作，误触会白白丢掉几十克线。这类不可逆的损失不该靠记性避免，所以默认拦，真丢加 `--force`。

**颜色名去掉所有空白再归组。** 从表格里粘过来的颜色名经常夹着制表符或换行，不清掉会把终端表格顶歪，也会让同一种颜色分成两组。

## 已知限制

- 一份存档就是一个人的库存，没有多用户/多人共享概念
- 颜色归组靠名字归一，`雾霾蓝` 和 `雾蓝` 不会自动认成同一个 —— 起名时统一一下
- 针号如果是日本号（`5/0`）这类没有单一数字的写法，会按原文归组，不跟你毫米针号混算
- 没有删除一条线、或修改它品牌/颜色/克重的命令。真要改就手动编辑 `crochet_data.json`，它是给人看的纯文本（改的时候注意别把 JSON 括号弄坏）
- 项目只有「在织 / 完工」两种状态，没有「搁置」
- 库存允许记成负数（用量估错很正常），只会标个 ⚠️ 提醒，不会拦你
